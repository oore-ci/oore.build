These tutorials take you from a Mac with nothing installed to a signed build
that testers can install. Each page ends on a result you can check, and links
to the next page.

## Set up Oore on one Mac

Everyone starts here. You install Oore in **Local Only**, the default, where
the control plane, web UI, runner, and artifact storage all run on one Mac and
only that Mac can sign in.

1. [Check that your Mac is ready](/start/prerequisites).
2. [Install Oore](/start/install).
3. [Complete first-run setup](/start/first-run).

You are done when the Oore web UI shows **Home** and **Settings > Runners**
lists one online runner.

## Then ship your app

Pick the platform you ship first. You can follow the other path later on the
same install.

<Cards>
  <Card title="Ship an Android app" href="/start/android/first-build">
    Build a debug APK, sign a release App Bundle, and deliver it to testers on
    Google Play.
  </Card>
  <Card title="Ship an iOS app" href="/start/ios/first-build">
    Build for iOS, sign it with an App Store Connect key, and deliver it to
    TestFlight and the App Store.
  </Card>
</Cards>

None of these pages needs External Access, an identity provider, GitHub,
GitLab, or object storage. Store uploads leave from your Mac, so Local Only is
enough to reach Google Play and TestFlight.

Two delivery options do need more setup, and the tutorials point to them
where they fit:

- Installing a build straight from Oore on a phone needs a URL the phone can
  reach. For iOS, that URL must use HTTPS.
- Letting other people sign in to Oore needs [External Access](/team/access).

If you are not sure Local Only fits your team, read
[Which setup do I need?](/concepts/which-setup) first.
