---
title: 'Send Notifications to Slack'
description: 'Post build failures, release uploads, and rollout changes to a Slack channel and mention the person who triggered them.'
status: implemented
---

Slack channels post a message when a build finishes, a runner goes offline, or a release or rollout changes state. Each message links to the build or release in Oore. The message can mention the person who triggered the build or release, from a list of Slack member IDs or a bot token lookup.

Oore sends every request from the backend host. Slack never calls back into Oore, so the backend stays private.

## What you need

- A Slack app with an incoming webhook for the target channel
- Optionally, a bot token from the same app with the `users:read.email` scope
- A **Public URL (HTTPS)** set to the browser-visible Oore URL under **Settings > General > Network settings**, so messages can link to the build or release
- The Owner or Admin role in Oore

## 1. Create the Slack app

1. In Slack, create an app for your workspace.
2. Under **Incoming Webhooks**, turn webhooks on and add a webhook for the channel. Copy the webhook URL.
3. To mention people, add the `users:read.email` bot scope under **OAuth & Permissions**, install the app, and copy the bot token. It starts with `xoxb-`.

## 2. Add the channel in Oore

1. Open **Settings > Notifications** and select **Add channel**.
2. Set **Type** to **Slack**.
3. Choose a **Project** to post only that project's events, or keep **All projects**. Runner alerts only go to channels for all projects.
4. Paste the webhook URL and, if you have one, the bot token. To mention people without a bot token, or to mention people who push to Git, list their Slack member IDs (see [Mentions](#mentions)).
5. Pick the events to send, or leave them all unchecked to send every event.
6. Save, then select **Test**.

The test message says whether mentions work for the email you signed in with, so a missing mapping or a mismatch between your Oore email and your Slack email shows up here.

## Events

| Event            | Sent when                                          |
| ---------------- | -------------------------------------------------- |
| Succeeded        | A build succeeds                                   |
| Failed           | A build fails; the message links to the build logs |
| Canceled         | A build is canceled                                |
| Timed out        | A build exceeds its timeout                        |
| Expired          | A queued build expires                             |
| Runner offline   | A runner stops reporting (all-projects channels)   |
| Release uploaded | A release is uploaded to a store track             |
| Rollout raised   | A staged rollout moves to a higher percentage      |
| Rollout halted   | A staged rollout is halted                         |
| Rollout complete | A rollout reaches 100%                             |
| Approval needed  | A release waits for approval                       |
| Release failed   | A release fails                                    |
| Tester feedback  | A tester sends feedback from the QA portal         |

Messages post within a few seconds of the change. If Slack does not accept a message, Oore tries again up to four more times over the next eight minutes; the delivery shows as pending until then. Delivery history for each channel is on its settings page.

## Tester feedback

Testers can select **Feedback** on the latest release in the QA portal. The note carries their device, OS version and app version, which the form fills in and the tester can edit, plus an optional screenshot. It shows on the build's **Timeline** tab and posts to the project's channels with a **View feedback** button. Feedback messages do not mention anyone; they name the tester instead, by display name, or by email when the tester has no display name. Webhook payloads always include the tester's email.

Anyone who can install the build can send feedback. Each person can send 10 notes per 10 minutes. Screenshots must be PNG, JPEG or WebP images of 5 MiB or less and need artifact storage.

## Mentions

Oore works out who to mention in this order:

1. **Slack member IDs on the channel.** Each line maps an Oore sign-in email or a Git username to a Slack member ID, for example `dev@example.com U0123ABCD` or `octocat U0123ABCD`. Builds started from Oore or the API match the sign-in email. Builds triggered by a Git push or merge request match the Git username. Releases match the email of the person who acted. This needs no bot token, so it works with an incoming webhook alone.
2. **The bot token.** If the email is not mapped, Oore looks it up with Slack's `users.lookupByEmail`. Git usernames cannot be looked up this way, so map them under Slack member IDs.
3. **Plain text.** Otherwise the message names the person by email or Git username without a mention.

To find a member ID in Slack, open the person's profile, select the **More** menu, and choose **Copy member ID**.

The test message checks the mapping for your own sign-in email first, then the bot token.
