Local Only lets one person use Oore from the Mac that runs it. These guides
open Oore to a team. Do them in this order.

## 1. Let people sign in

[Configure External Access](/team/access) so people can sign in from their
own devices over HTTPS. Then pick how they sign in:

- [External Access (OIDC)](/team/access/oidc) with Google, Microsoft Entra ID,
  Okta, Auth0, or Keycloak. Choose this unless you already run an access
  proxy.
- [External Access (Trusted Proxy)](/team/access/trusted-proxy) when an
  existing authentication proxy already checks who people are.

## 2. Add people

1. [Invite a team member](/team/invite) with an instance role.
2. [Manage roles and project access](/team/roles) for the projects they need.
3. [Disable or restore a user](/team/disable-users) when their access should
   change.

Instance roles control actions across Oore. Project roles control access
inside one project. The backend checks both, so hiding a button in the web UI
is not what keeps someone out. See [Roles and permissions](/reference/roles)
for the full matrix.

## 3. Keep the team informed

[Send notifications to Slack](/team/notifications) for failed builds, store
uploads, rollouts, and approvals.
