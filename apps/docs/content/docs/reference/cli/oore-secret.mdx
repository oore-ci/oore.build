---
title: '`oore secret`'
status: implemented
description: 'Set, list and delete encrypted secrets for the instance, an app or a pipeline.'
---

```text
oore secret list   [--project <ID> | --pipeline <ID>] [--json]
oore secret set    <NAME> [--project <ID> | --pipeline <ID>] [--file PATH | --from-env VAR] [--json]
oore secret delete <NAME> [--project <ID> | --pipeline <ID>] [--yes] [--json]
```

Secrets are what `${{ secrets.NAME }}` reads in a
[pipeline file](/reference/config/oore-yaml-v2). Without `--project` or
`--pipeline` the command works on the instance's secrets, shared by every app.
A pipeline's secret wins over its app's, and an app's over the instance's.

The value never comes from an argument, so it stays out of shell history and
process lists. `set` reads it from standard input (a hidden prompt in a
terminal), from a file with `--file`, or from a variable with `--from-env`. One
trailing newline is dropped. Values are never printed.

| Subcommand | Effect                                                                                       |
| ---------- | -------------------------------------------------------------------------------------------- |
| `list`     | List the names in the scope and when each changed.                                           |
| `set`      | Create the secret, or replace its value if it exists.                                        |
| `delete`   | Delete it. Builds that read it fail until it is set again. Needs `--yes` without a terminal. |

```bash
printf '%s' "$SENTRY_TOKEN" | oore secret set SENTRY_TOKEN --project proj_123
oore secret set GOOGLE_SERVICES --pipeline pipe_456 --file android/app/google-services.json
oore secret list --project proj_123
```
