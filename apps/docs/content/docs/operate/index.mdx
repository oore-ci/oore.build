These guides keep an Oore instance running and grow it when your team needs
more. Start from the one-Mac Complete install. Add one piece at a time, and
check it works before you add the next. To decide what to add, read
[Which setup do I need?](/concepts/which-setup).

## Reach Oore from other devices

- [Connect the hosted UI](/operate/access/hosted-ui) at `ci.oore.build`.
- [Connect Cloudflare Tunnel and Access](/operate/access/cloudflare-access)
  to put a loopback backend behind HTTPS.
- [Self-host the static UI](/operate/access/self-hosted-ui).
- [Add another Oore instance](/operate/instances/add) to the same browser, and
  [switch between instances](/operate/instances/switch).

## Build on more Macs

- [Add a Direct macOS runner](/operate/runners/direct) on another Mac.
- [Route builds with runner labels](/operate/runners/labels).
- [Run builds in VMs](/operate/runners/vm-isolation) for a clean machine per
  build.
- [Manage dependency caches](/operate/runners/caches).
- [Split Oore across Macs](/operate/deploy/split-roles), or
  [run a Web node on Linux](/operate/deploy/linux-web-node).

## Store artifacts

[Configure artifact storage](/operate/storage/artifacts) on the Mac or in S3
or R2.

## Maintain

1. [Monitor Oore](/operate/maintain/monitor).
2. [Create and verify a backup](/operate/maintain/backups/create) before every
   upgrade.
3. [Upgrade Oore](/operate/maintain/upgrade) on the current channel, or
   [choose a release channel](/operate/releases).
4. [Restore a backup](/operate/maintain/backups/restore) when you need to.

## Fix problems

- [Troubleshoot Oore](/operate/troubleshoot) routes each symptom to the right
  check.
- [Reset an Oore installation](/operate/recover/reset) only after narrower
  fixes fail.
- [Report an issue](/operate/support/report-an-issue) with the details
  maintainers need.
- [Known limitations](/reference/known-limitations) lists what Oore does not
  support.
